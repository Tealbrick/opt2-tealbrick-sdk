# @opt2-tealbrick/manifest

The one owner of opt2 contract primitives (SDK-API §2, CORE §3): manifest validator (schema + every MANIFEST cross-field rule), `validateInput`, `withStandardOps`, MCP tool names, `renderSkill`, RFC 8785 JCS + sha256 digests, Ed25519 keys and JWS (`signJws`, `signJwsWithSigner`, `verifyJws`), key sets and the announcement trust rule, assertions, AES-256-GCM sealing, opaque values, ULIDs, every token verifier and issuer-side signer (grant, call/hook/bridge-op proofs, tickets, config, slice, pairing code, agent session, release index), and the decision functions `gate()` (bridge) and `authorize()` (app).

Runtime deps: `@opt2-tealbrick/spec`, `ajv`. Node 24+. Copying any of these primitives elsewhere is a CI failure.

0.1.23 (spec 0.1.46, GRANT-PRD): the grant claim set accepts an optional `prd` (a product id, `^[a-z][a-z0-9-]{1,31}$`) for companion grants; `signGrant` and `verifyGrant` shape-check it. A verifier older than 0.1.23 refuses a grant that carries `prd` (closed claim set), so deploy readers before Core mints it.

0.1.31 (spec 0.1.66, C330(1), M4b; QA-SPEC48-2/-3): `listing: "lazy"` guards for bridges without a fallback. M-OP-13 `listing_invalid`: a lazy op that is dynamic, or a manifest with any lazy op whose `requires.bridge` is absent or below `LAZY_LISTING_MIN_BRIDGE` (new export; "0.2.9" is a reservation, the release lead sets the real first bridge with `lazy_tools`). `BRIDGE_FEATURES` row `lazy_listing` → that version (requiredBridgeVersion). Still pins spec 0.1.57, whose schema refuses `lazy` itself; the rule bites from the re-pin to spec ≥ 0.1.66 (tests run both branches).

0.1.30 (spec 0.1.57, C274c/C274d, app events): re-pin spec 0.1.57. The validator reads manifest `events` (MANIFEST §16): M-EV-1 `event_name_invalid` (unique names, the name pattern, never `tb.`, no events in a manifest `tb`), M-EV-2 `event_schema_invalid` (payloadSchema: object root, compiles in Ajv 2020 STRICT mode, ≤ 8 KiB JCS, the M-OP-8 limits), M-EV-3 `event_visible_with_invalid` (visibleWith = an agent op of the manifest, not dynamic), M-EV-4 `event_schema_invalid` (no top-level `summary`); a schema failure inside `events[]` carries the M-EV rule and code. `BRIDGE_FEATURES` row `events` → bridge 0.2.7 ("app events (C274)"; a manifest with the `events` key, also an empty list, since an older validator refuses the key). New shared helpers for the SDK and the bridge (L1): `eventDecl(manifest, name)` (manifest declarations, `PLATFORM_EVENTS` for `tb.*`), `eventScopeType(manifest, decl)` (the visibleWith op's scopeType, null = unscoped), `eventVisibleCrud`, `validateEventPayload(decl, data)` (cached compile, ≤ 2 KiB JCS → `event_too_large`, schema → `event_payload_invalid`), `eventVisibleToGrant(manifest, decl, claims, authority)` (the tools/list rule for visibleWith; `authority: "owner"` skips `op.crud ⊆ grant.crud` only, as gate() does for scoped ops), and the wire limits (`EVENT_KEY_RE`, `EVENT_DATA_MAX_BYTES`, …). SPEC GAP fix (admin queue b): `activeKeyRequirements` keeps a key in force only when its own `when` holds AND, when it names a `step`, that step's `when` holds (a key in a skipped step is not in force); stored setting defaults are unchanged. A key that must stay in force while its step is skipped (Knowledge: research mode uses the provider keys of a skipped models step) belongs in no step or in a step that is shown.

0.1.29: re-pin spec 0.1.54 (types: slice bridge.caps); no behaviour change.

0.1.28 (spec 0.1.52, C268 B / C268c, C283c): the hook variant of the call proof allows an optional `bd` = `sha256:<64 hex>` of the exact hook request body bytes (the same digest format as `bd` on assertions); a malformed `bd` is refused by the claim shape, and `bd` on an op proof or a bridge-op proof stays refused (`op proof shape` / `bridge-op proof shape`). `verifyHookProof()` takes the optional binding `bodyDigest`: when the proof carries `bd`, it must equal `bodyDigest` (else `invalid_token`; a proof with `bd` and no `bodyDigest` is refused, fail closed); a proof without `bd` is not compared (a later slice flag will make it required). The bridge sends `bd` only to an app whose claim or status lists `"bd"` in `proofClaims` (miniapp-sdk 0.1.36 does). `SDK_AUDIT_ACTIONS` gains `scope.snapshot_backfill` and `scope.offer_accepted`; the standard operation `tb.scopes_set` takes the optional input `acceptOffer: {adds: ["read" | "create" | "update" | "delete", ...]}` (at most 8 items; a closed object). No new dependency.

0.1.27 (spec 0.1.50, C283 A1, C277): `gate()` skips the step `op.crud ⊆ grant.crud` for an op WITH a `scopeType` (the app's own owner-set access may be primary above the Portal grant; the SDK `authorize()` decides, and an SDK that does not know the rule still refuses `op.crud ⊄ grant.crud`); an op without a `scopeType`, and every other gate step, are unchanged. `authorize()` reads `access.authority`: `"owner"` → `op.crud ⊆ access.crud`; absent, `"bounded"` or any other value → `op.crud ⊆ grant.crud ∩ access.crud`; a scoped op that passes sets `Decision.admittedBy` (`"app_owner_row"` or `"portal_grant"`) on its later hold or run decision, never on a refusal. `opVisibleToGrant()` is unchanged and stays the narrower side: everything it lists passes `gate()`, but `gate()` now also passes a scoped op above `grant.crud` (the bridge lists those through the app's `scope_summary` `admittedOps`). `verifyHookProof()` (C268 A) takes the optional bindings `sub` and `call`: when given, the proof `sub` must equal `sub` and the proof `call` must equal `call`, else `invalid_token` (a mismatch does not use up the one-time proof); callers that pass neither behave as before. `hookCallerRef(call.caller)` builds the expected `sub` of a hook request: `tb:agt:<id>` for an agent, `tb:ins:<id>` for an app instance, `""` (never matches) for anything else. No new dependency.

No API or behaviour change of this package. `@opt2-tealbrick/miniapp-sdk` 0.1.34 and `@opt2-tealbrick/conformance` take it through the workspace link; manifest 0.1.26 must be released and mirrored before the miniapp-sdk 0.1.34 tag (C215). 0.1.25 (C238, security): `AGENT_DOCUMENT_RULES.deniedScriptTypes` = `["importmap", "speculationrules"]`: `<script>` elements of these types are removed in EVERY mode, also with `allowScripts: true` (a speculation rules script declares prerender and prefetch requests, an import map can point module loads off-site). The type is read with ASCII white space trimmed, ASCII lower-cased and anything after `;` ignored. `sanitizeAgentDocument()` is in `@opt2-tealbrick/miniapp-sdk` 0.1.30.

0.1.24 (C238, C230, C232): `AGENT_DOCUMENT_RULES` is the rule list for agent-written HTML served as a `/_d/` document, as frozen data next to `VIEWER_HEADER_FLOOR` so that the SDK sanitiser, its tests and conformance read one list: the elements that are removed (`link` with every `rel`, `base`, `meta[http-equiv]`, `form`, frames, `object`/`embed`/`applet`/`portal`/`fencedframe`, `noscript`), the attributes that go (`ping`, `srcdoc`, `on*` unless the app opts into scripts), the URL attributes and the three allowed URL forms (a `#fragment`, a raster `data:image/...`, a path under the app's `assetPrefix`), the CSS image functions and at-rules (`url(`, `image(`, `image-set(`, `cross-fade(`, `element(`, `src(`, `@import`, with or without a vendor prefix), the SVG presentation attributes and SMIL attributes that get the same CSS check, and the limits (2 MiB input, tree depth, 256 attributes per tag and 100 000 tags counted over the whole source before any parse), the text-slot attribute `data-tb-text`. With it `AGENT_DOCUMENT_MARKER` (`<!-- tb:sanitized v1 -->`), `AGENT_DOCUMENT_MAX_BYTES` and `AGENT_DOCUMENT_UNAVAILABLE_TEXT`. The manifest package holds no sanitiser and no HTML parser; `sanitizeAgentDocument()` is in `@opt2-tealbrick/miniapp-sdk` 0.1.29.
